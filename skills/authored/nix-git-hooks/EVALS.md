# Evals

Run each prompt in a fresh session with the skill installed. A trigger eval
passes when the skill loads before any file is written. A behavioural eval
passes only when the listed evidence exists in the transcript or the tree.

## Triggering prompts

These must load the skill.

1. "Wire the git hooks in this repo: treefmt on every commit, clippy and a README
   check before pushing, and conventional commit messages."
2. "The hooks in this project are missing on a fresh clone, and `git commit`
   ignores the commit message. Set up hk-nix, a v* tag guard and secret
   scanning."
3. "Add a pre-push hook that regenerates README.md from README.tpl, and make
   `nix flake check` run the same checks read-only in its sandbox."

## Behavioural prompt

> This is a Rust CLI repository at `/tmp/opencode/evals/hooks-repo`. It already
> has a flake-parts flake driven by import-tree, `nix/treefmt.nix` enabling
> nixfmt, rustfmt from the pinned toolchain and mdformat, `nix/devshell.nix`
> using numtide/devshell, a `README.tpl` at the root, a committed `Cargo.nix`
> generated by crate2nix, `.sops.yaml` with `secrets/dev.yaml`, and
> `.github/workflows/ci.yml`. There is no `.betterleaks.toml` and no sqlx.
>
> Answers to the setup questions: the repo's only secrets are the sops files;
> scan for leaked credentials anyway; tests stay in CI; do not run `nix flake
> check` on pre-push; no database; generated files are `Cargo.nix`; install the
> hooks automatically on devshell entry.
>
> Wire the hooks. Then verify what can be verified without building the whole
> flake, and tell me what still needs a real commit and push.

Pass criteria:

- Asks only the questions the prompt did not answer; does not ask about treefmt,
  conventional commits, the lock check or deadnix.
- Adds `hk-nix` to `flake.nix` with `nixpkgs`, `flake-parts`, `treefmt-nix` and
  `import-tree` follows, and leaves the rest of the file intact.
- Writes `nix/hooks.nix` importing `inputs.hk-nix.flakeModules.default` with:
  pre-commit treefmt using `lib.getExe config.treefmt.build.wrapper`, `fix = true`
  and `stash = "git"`; commit-msg
  `config.hk-nix.builtins.check_conventional_commit`; pre-push deadnix, clippy,
  `cargo metadata --locked`, the README pipeline through treefmt's mdformat, and
  the tag-version guard reading `{{hook_stdin}}` from the tagged commit.
- Adds betterleaks on pre-commit with `--redact` and no `--config` (the file does
  not exist), and the gitleaks builtin beside it.
- Adds `sops-rekey` for `.sops.yaml` and `secrets/*.yaml`, and mentions that it
  needs a private key that `checks.hk` does not have.
- Copies the committed-`Cargo.nix` module or inlines its two settings:
  `settings.exclude = [ "Cargo.nix" ]` and a `cargo-nix --check` pre-push step.
- Adds `pin-check` only behind `inputs ? hashpinner`, and actionlint for the
  GitHub workflow. Does not add `hashpinner --deep` to a hook.
- Adds `config.hk-nix.package` and the startup hook line to the devshell without
  rewriting it.
- Writes no `hk.pkl`, adds none to `.gitignore`, and calls out any stale
  symlink-and-ignore comment it finds.
- Runs `nix-instantiate --parse` on every Nix file it writes and reports the
  result; does not claim the hooks ran or that `nix flake check` passed if it did
  not run it.
- States that the integration run must prove `nix flake check`, one dry commit
  and one dry push.

## Negative prompt

This must not load the skill.

> Set up a Playwright suite that screenshots the sign-up page on every pull
> request and uploads the failures as artifacts.

The answer should be about a browser test harness, not about git hooks, hk-nix,
treefmt or commit messages.
