# Evaluations

## Triggering prompts

Each of these must load this skill.

1. "We have a design for a new CLI called `spindle`. Scaffold the Cargo workspace
   with the house workspace lints and a dendritic Nix flake, and wire crate2nix into
   it."

2. "This repo is still a single-package Cargo project. Set up a Cargo workspace under
   `crates/*`, add grouped workspace dependencies, a `rust-toolchain.toml`, a
   `justfile` and a `README.tpl` generated by cargo-readme."

3. "Add crate2nix to our flake. We have four binaries and about 180 crates in
   `Cargo.lock`, so I probably want `Cargo.nix` committed, but ask me first. Also add
   the treefmt and devshell modules to the dendritic layout."

## Behavioural prompt

**Repository state.** `/tmp/opencode/evals/acme` is a clean git repository with no
`flake.nix`, no `nix/`, no `justfile` and no `README`. `git remote get-url origin`
returns `git@github.com:sshine/acme.git`. The tree is:

```
Cargo.toml
src/main.rs
```

`Cargo.toml`:

```toml
[package]
name = "acme"
version = "0.4.2"
edition = "2021"

[dependencies]
clap = { version = "4", features = ["derive"] }
```

`src/main.rs` starts with a `//!` block describing the command and contains a small
clap parser.

**Prompt.** "Set up a Cargo workspace and its dendritic Nix flake for this repo.
Keep the binary as `acme` and add an internal library crate `acme-core` that we
publish; the binary stays unpublished. I'd like the README generated from the crate
docs. Ask me anything you need before writing."

**Pass criteria.**

1. It asks in one batch and stops before writing. The batch covers member names and
   responsibilities, which crates publish, native/system libraries, whether to commit
   `Cargo.nix` (with the large-closure / several-binaries recommendation), the MSRV
   for the published library, and the README shape. It does not ask about resolver,
   edition, workspace lints, treefmt, the dendritic layout, or the license.
2. The root `Cargo.toml` keeps version `0.4.2`, uses `resolver = "2"`,
   `members = ["crates/*"]`, `edition = "2024"`, both workspace lints, a grouped
   `[workspace.dependencies]`, `rust-version` because `acme-core` publishes, and
   `[profile.release]`.
3. `crates/acme/Cargo.toml` and `crates/acme-core/Cargo.toml` inherit version,
   edition, license and repository; both carry `[lints] workspace = true`; `acme`
   declares `acme-core` with both `path` and a `version` equal to the workspace
   version.
4. `rust-toolchain.toml` pins `stable`, `rustfmt`, `clippy` and both musl targets.
5. `flake.nix` has exactly the base inputs (nixpkgs channel tarball, flake-parts,
   import-tree, rust-overlay, treefmt-nix, devshell, crate2nix) with the follows
   relationships, and `nix/` contains systems, rust-overlay, treefmt, devshell,
   packages, `_package`, `_cargo-nix` and release modules. The devshell's hook package
   and startup entry are guarded by `config ? hk-nix`.
6. The justfile has the base verbs plus `cargo-nix`/`cargo-nix-check` only if
   committed mode was chosen; `readme` and `readme-check` pipe through `mdformat`.
7. `README.tpl` has `# {{crate}}`, an Installation block, a NixOS overlay section,
   `## CLI` with `{{readme}}`, and a License line. The generated `README.md` is
   produced by the recipe, not written by hand.
8. It does not create `nix/hooks.nix`, `nix/binary.nix`, any CI workflow, any release
   workflow, or a git tag.
9. It reports which commands it ran and which are left for the integration run, and
   does not claim the workspace builds without `nix flake check` or `just ci`.
10. It ends by naming the next phase: **Wire the repository's git hooks.**

## Negative prompt

"Our `v0.3.0` tag produced a broken static musl tarball and the `.sha256` sidecars
don't match the assets. Fix the release workflow and re-tag."

This describes the tag-driven binary release, not workspace scaffolding, and must not
load this skill.
